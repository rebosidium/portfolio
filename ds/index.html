The shared building blocks of this portfolio.

Shared components, states and responsive templates. Open View code to reuse the actual markup, styles and behavior on a new project page.

Naming conventions

Names describe purpose: family / role, followed by a variant when needed. Light and Dark describe prepared themes; Hover, Pressed and Keyboard focus describe interaction states. Responsive layouts and motion preferences keep their own labels.

Each type recipe has one name, with its current uses and responsive differences listed below. Token names describe the design decision, with the CSS key beside the value. Stable renderer keys and specimen links stay unchanged.

Based on Adobe Spectrum naming guidance and the USWDS token approach.

IMPLEMENTATION GUIDE

For AI agents

Where to edit. How to reuse.

This project serves static HTML, CSS and JavaScript. Node renders shared markup at build time. Start with the repository’s AGENTS.md, shared/AGENTS.md and shared/README.md; use this guide as a map to the current implementation.

Source ownership

Paths are relative to the site repository

Navigation before initialization

The shared head bootstrap marks JavaScript availability before the header can paint. A mobile page keeps its normal hamburger layout while navigation initializes; an early tap is remembered until the handlers are ready. The inline link fallback is reserved for JavaScript being disabled or navigation failing its 3-second deadline. Source: shared/navigation-boot.js and shared/site-ui.css. HOME, About, generated reading pages and header previews share this rule; reading content keeps its normal top spacing while initialization is pending.

Neighbor media preparation

HOME and About prepare each other’s heavy media only after their own assets finish. HOME prepares one correctly sized file for every About photo. About completes its own photo set first, then prepares the homepage poster and startup portrait ZIPs. Remaining portrait ZIPs require a reported 4G connection of at least 5 Mbps, RTT at most 150 ms, no cellular type and a total set within 26 MiB. Unknown network quality prepares only the startup set. Save-Data, 3G or slower, offline and hidden pages pause the queue; reduced motion prepares only the static portrait.

The queue uses one low-priority request, 750 ms of page quiet, versioned HTTP-cache URLs and bounded retries. It downloads encoded bytes without initializing the neighboring page or decoding its animation. Source: shared/neighbor-prefetch.js, shared/neighbor-prefetch.mjs and shared/media-selection.mjs; the build generates home/assets/neighbor-prefetch.js. This behavior is limited to the two production routes and stays disabled in DS previews and other pages.

How layout works

Centered page and reading-column widths, mobile gutters and type come from Layout & spacing, Typography and their tokens. Page CSS owns arrangement; shared CSS owns component appearance. Reuse existing classes and semantic tokens.

Mobile mode depends on width and pointer capability. Keep CSS and JavaScript aligned with shared/layout-contract.mjs; the build rejects mismatches. HOME uses measured sticky scenes and overlapping work panels. About uses native reading flow followed by the shared footer overlap. Preserve their existing viewport and resize handling when changing composition.

Reuse before extending

Open a component or template’s View code → Use for its current renderer recipe, then check Setup & dependencies. Import renderComponent or renderArticlePage from shared/library.mjs in build-time Node code. The reading-page renderer supplies the existing header, Back, prose, footer and working controls. Use confirmed content; add a shared pattern only when an actual page needs it.

Build a project page

  1. Gather confirmed text and images. Mark missing details as draft.
  2. Open the reading-page recipe → Use. Supply the title, canonical URL, introduction and sections to renderArticlePage; reuse current components before extending them.
  3. For a production page, store its confirmed content in a shared JSON file and register an article entry in shared/site-pages.mjs. The build renders its exact document. Direct renderer calls still return HTML without writing or publishing it.
  4. In that one registry entry, declare the route, exact document/files, component consumers and contentSource. Build-time usage stamps, dependency fingerprinting and publication checks use the same entry. Publication still requires a reviewed release; adding a route does not advertise it in navigation.
  5. Run the build and check commands below. Verify the new page on desktop and mobile, including shared controls, focus, reduced motion and existing consumers.
  6. Commit the finished change. Review the dry run with node publish.mjs --site=home --expect-base=<reviewed-public-SHA>, then add --publish for the authorized release. Keep draft pages out of navigation and the sitemap unless requested.

Change and verify

  1. Edit canonical sources. Generated shared:… regions, home/assets/site-ui.css, home/assets/site-controls.js and DS catalogs are build output.
  2. Run the HOME release pipeline from the repository root:
node refresh-release.mjs --site=home
node refresh-release.mjs --site=home --check

Verify desktop/mobile layout and affected states; recheck existing consumers after a shared change. Preserve keyboard focus, reduced motion, readable fallbacks, portrait startup and Resume downloads. Register new routes in shared/site-pages.mjs; keep component ownership/dependencies in shared/component-registry.mjs. Declare DS releases in shared/design-system.json; revisions and fingerprints are generated.

Maintenance rule: update this map only when ownership, layout architecture or the workflow changes. Current values, states, recipes and versions live in the linked sections and View code.

Recommendations / Living ink

1062.5 ms + ≤162.5 ms stagger · total 1250 ms

Letters lift from their original typeset positions, flutter and rearrange into the next quote. Matching characters travel within six font sizes; excess letters dissolve over475ms and new letters appear over812.5ms. All letter timings run25%longer with gentler cubic-bezier(.45,0,.25,1) easing. The original quote remains intact under an aria-hidden temporary layer. Letters animate opacity and transform; one temporary layer softly blurs0→0.65→0.35→0px over1250ms. In the final250ms (1000–1250ms), complementary ease-in-out opacity animations dissolve the copies into the exact original text run. Copies are fully transparent before cleanup, avoiding a glyph-shaping or rasterization snap. The original text at rest stays sharp. Responsive excerpts keep one visible paragraph; glyph measurements use that paragraph when desktop and mobile text differ. The author fades in over400ms after a375ms delay.

Trigger, playback & accessibility

Playback & reverse

Rapid selection cancels old copies; resize, font swap, offscreen/hidden/menu settle the selected quote. Tallest-slide grid reserves height. Shared browser handling

  • Viewport. Mobile and coarse-pointer HOME scenes use stable 100svh; work screens use 100lvh. The menu uses 100dvh and safe-area insets. Browser toolbar movement does not rebuild the scroll scene.
  • Copy. AI brief calls clipboard.writeText directly from the click, preserving Safari’s user activation. Selection-based copy and Manual copy handle failures on every platform.
  • PDF. A prepared application/octet-stream Blob avoids Safari’s inline PDF preview while keeping the .pdf filename. All platforms share this handler; the original link works before preparation.
  • Appearance and motion. Shared tokens, native SVGs and responsive images; capability-based hover, disabled native tap overlay and visible keyboard focus. Reduced motion uses a static portrait and ordinary reading flow.
